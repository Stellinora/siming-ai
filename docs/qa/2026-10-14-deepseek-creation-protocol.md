# DeepSeek 立项调用修复 — 2026-10-14

## 实际故障

1. 第一类错误：本机诊断记录显示 `deepseek-flash` 思考耗尽 4096 输出额度，网关关闭思考重新获取工具调用；下一步又使用默认思考模式回放这个无思考工具事务，DeepSeek 返回 HTTP 400，要求 `reasoning_content`。
2. 第二类错误：当前只开放阶段资料与生成工具，模型返回 `get_creation_artifact` 和未开放的 `list_creation_entities`。整批被拒绝，但界面误导性地显示为“对话上下文处理失败”。该轮上下文仍在容量内。

## 修复

- 将输出上限恢复后实际采用的思考模式绑定提供商、模型、端点和协议，随当前工具事务保存。后续调用及连接恢复沿用该模式；新用户回合不继承。内部状态不发送给供应商，未伪造思考内容。
- DeepSeek 非流式响应也保留真实 `reasoning_content`；存在合法工具调用时允许正文为空。
- 立项助手复用工具名称拒绝契约：格式正确但包含未开放工具时，整批不执行，持久化拒绝回执，由同一模型重新选择。最多两次纠正机会，第三次拒绝结束；应用不替模型选择类别，也不执行合法前缀。
- 实体读取指引明确要求先单独调用 `set_tool_categories` 选择 `creation_entities`。
- PC 和手机协议错误明确提示工具校验失败、当前批次未执行、此前进度保留，避免错误建议缩小上下文。
- 手机立项同步整批拒绝和有界纠正。手机原先没有 PC 的临时关闭思考恢复分支，本次没有添加该分支或修改全局思考默认值。
